and copied callback/safe return/expiry/consent recovery. Each engine additionally
runs two malformed boot-marker controls.

The simulator preserves canonical preset URL/query validation, signed token exchange,
state, nonce, PKCE and Apple's `response_mode=form_post`. An explicit fixture handoff
enters a separate reserved provider site through a strict loopback CONNECT proxy.
This prevents macOS AppSSO from taking ownership of the simulated Apple flow and
avoids WebKit's interrupted cross-site redirect metadata. Apple still submits a
native cross-site POST: the actual HTTPS owner must receive the sealed transaction
cookie and must not receive the Lax application session cookie. Browser URL, method
and body must match that server receipt. Unknown traffic, unexpected request failures,
secret leakage, incomplete cancellation and unbounded cleanup remain failures.
See [the fixture boundary](../provider-auth/README.md#reproduce-acceptance-after-the-final-graph-is-available).

## Reproduced defects and corrections

- The original redirect-interception probe failed all six browser/redirect cases:
  Chromium/Firefox followed the redirect beyond interception, and WebKit rejected
  fulfilled redirects. The native CONNECT experiment exposed macOS Apple AppSSO
  and WebKit native-navigation reporting. Replacing transport with an owned
  simulation handoff retained strict assertions and produced the complete green matrix.
- A first provider alias used the application's site and failed all six Apple
  callback-cookie assertions: the Lax session cookie was sent. The final alias is
  on a separate reserved site; those assertions remain intact.
- Google's initial login incorrectly requested Calendar permission. The focused
  browser test failed because identity-only login contained the Calendar scope.
  Login now requests only identity scopes for Google and Auth0. Their first server
  operation requests separate API consent, consent does not resubmit the operation,
  and the next deliberate click produces exactly one server API call. The focused
  Google test, 14 signed HTTP tests and all 54 browser cases pass.
- Auth0/Microsoft provider logout had no application-level evidence. Two signed
  HTTP cases now prove exact canonical end-session destinations and public query
  fields, session-cookie clearing, retired old-cookie authority and absence of
  tokens in redirect URLs. The simulator never follows those destinations. The
  README documents explicit provider logout/revocation requests separately from
  the application's local logout button.
